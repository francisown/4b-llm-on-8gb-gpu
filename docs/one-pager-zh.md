# 一页纸 · 8GB 大模型推理交付

**一句话**：在单张 RTX 5060 8GB 上，把 4B 大模型的量化、质量评测、调度调优、服务化和离线交付完整走通一遍，每一步都留下可复算的原始数据。

---

## 三组数字

| | 数字 | 条件 |
|---|---|---|
| 单卡输出吞吐 | **5,693 tok/s** | Qwen3-0.6B，并发 64，256in/128out，成功率 100%（并发 1 → 64 吞吐涨 21.4 倍） |
| 4B 模型压到 | **3.568 GiB**（较 BF16 缩小 59%） | 自制 W4A16 INT4-AWQ；相对第三方 FP8，并发 1 吞吐 +43.0%、并发 4 +30.0%（同会话 3 轮均值，批内极差 ≤0.6%） |
| 交付包在干净环境实机通过 | **7.49 GiB** | 含模型、运行时、网关、Compose、SHA-256 校验 |

> 第一行的模型是 **Qwen3-0.6B**（用它的原因是够小，能把并发拉到 64 而不撞显存），后两行是 **Qwen3.5-4B**。两个不同世代的模型，不要互相解释。

---

## 做了什么

**1. 量化。**写了两套量化脚本：FP8_BLOCK，以及 W4A16 非对称 INT4-AWQ。AWQ 侧用 C-Eval `dev` 校准 128 条、逐层校准单个 DecoderLayer、CPU offload，200 个线性权重以 packed INT4 保存，`lm_head` 与敏感投影保留 BF16。

**2. 评测。**固定 200 题 C-Eval `val`（覆盖 52 科目，样本 SHA-256 冻结），校准集与评测集互不重叠以避免数据泄漏，提示词、题序、答案解析、`temperature=0` 全部固定。

值得说的发现：四个模型——BF16、第三方 FP8、自制 FP8、自制 INT4——**总分完全相同，都是 141/200**。但逐题答案一致率分别是 100% / 96.5% / 98.0% / 87.0%，其中 INT4 有 26 道题的选择与 BF16 不同。

> 总分相同不等于模型等价。200 道单选题的 Wilson 95% 区间是 63.84%–76.39%，根本不足以证明等价。

**3. 调优。**并发 sweep 到 64；长上下文与 `max-num-seqs` 边界实验；Prefix Cache 冷/热前缀对照；Chunked Prefill 混合负载；MTP-4/5 与 N-gram 推测解码对比。推测解码里 MTP-5 把并发 4 吞吐从 104.26 提到 351.37 tok/s，**但 8GB 显存装不下"较长上下文 + 较高并发 + CUDA Graph + 激进 MTP"这个组合**，稳定交付包因此退回更保守的 N-gram 配置。

> 最优配置和能稳定交付的配置，不是同一个东西。这是实测出来的边界，不是猜的。

**4. 服务化与交付。**FastAPI 网关：SSE 流式（含 TTFT 与端到端延迟）、连接/读/写/连接池四类独立超时、有界并发与队列、HTTP 429 背压、Prometheus 指标、`/live` 与 `/health` 分离、单行 JSON 日志、非 root 镜像。**9 个不依赖真实模型和 GPU 的 pytest**，覆盖正常、校验失败、上游超时/断连/HTTP 错误、容量拒绝与排队超时。

## 边界（不含糊的部分）

- 所有数字只适用于本机硬件、vLLM 0.29.0 与短上下文条件，不外推到其他 GPU 或长上下文业务。
- BF16 checkpoint 装不进 8GB 显存，它是在 CPU 上分层跑出来的质量基线，**它的延迟不能和 GPU 常驻模型比较**。
- 200 题单选题只能说明"在这 200 题上没观察到差异"，自由文本、代码、长上下文与真实业务数据都需要单独评测。
- 成本计算器是容量成本估算，不含网络、存储、人工、税费与冗余，不能冒充云 API 的完整报价。
