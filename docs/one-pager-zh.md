# 一页纸 · 8GB 大模型推理交付

**一句话**：在单张 RTX 5060 8GB 上，把 4B 大模型的量化、质量评测、调度调优、服务化和本地离线交付完整走通一遍，每一步都留下原始证据。

---

## 三组数字

| | 数字 | 条件 |
|---|---|---|
| 4B 模型压到 | **3.568 GiB**（比 BF16 小 59%） | 自制 W4A16 INT4-AWQ；比 FP8 小 32% |
| INT4-AWQ 输出吞吐 | 并发 4 时 **333.90 tok/s** | 256-in / 128-out，temperature 0，3 轮均值；TTFT p50 251.73 ms |
| 真实 vLLM 2 小时 soak | **67,530 请求，0 错误** | c=4，9.379 req/s，p95 458.12 ms；另有 2 小时 mock gateway soak，140,178 请求 |

质量部分是真正值得讨论的：BF16、第三方 FP8、自制 FP8、自制 INT4 在冻结 C-Eval 集上都拿到 **141/200**，但 INT4 与 BF16 只有 **87.0%** 逐题一致，改变了 26 道题的答案。总分相同不代表模型等价；200 题的 Wilson 95% 区间是 63.84%–76.39%，不足以证明等价。

Qwen3-0.6B 的 5,693 tok/s（c=64）只作为引擎批处理测试负载放在主 README 的附录，不是交付模型数字。

---

## 做了什么

**1. 量化。**两套脚本：FP8_BLOCK 与 W4A16 非对称 INT4-AWQ。AWQ 侧用 C-Eval `dev` 校准 128 条、逐层校准单个 DecoderLayer、CPU offload，200 个线性权重以 packed INT4 保存，`lm_head` 与敏感投影保留 BF16。

**2. 评测。**固定 200 题 C-Eval `val`（52 科目，样本 SHA-256 冻结），校准集与评测集不重叠，提示词、题序、答案解析、`temperature=0` 全部固定。除准确率外，还报告逐题一致率、修正的 BF16 错题和损失的 BF16 对题。

**3. 调优。**并发 sweep 到 64；长上下文与 `max-num-seqs` 边界实验；Prefix Cache 冷/热前缀对照；Chunked Prefill 混合负载；MTP-4/5 与 N-gram 推测解码对比。MTP-5 把并发 4 吞吐从 104.26 提到 351.37 tok/s，**但 8GB 显存装不下“较长上下文 + 较高并发 + CUDA Graph + 激进 MTP”这个组合**，稳定交付包因此退回更保守的 N-gram 配置。

**4. 服务化。**FastAPI 网关：SSE 流式（含 TTFT 与端到端延迟）、连接/读/写/连接池四类独立超时、有界并发与队列、HTTP 429 背压、Prometheus 指标、`/live` 与 `/health` 分离、单行 JSON 日志、可选 API Key 认证、按身份限流、非 root 镜像。**19 个 pytest** 不依赖真实模型和 GPU。

**5. 部署。**两副本 Kubernetes 网关、readiness/liveness、PDB、零停机滚动与回滚：集群内 100 请求 0 错误、326.53 tok/s；压测中强杀 1 个 Pod 的 300 请求 0 错误。HPA 2→4→2 另用 CPU 指标 + mock upstream 验证（45s / 90s）。后续 WSL2 k3s smoke test 把 vLLM 放进集群，占 `nvidia.com/gpu: 1`，配 2 个 gateway 副本：100 请求 0 错误、147.17 tok/s（宿主路径 327.51 tok/s）。这是功能验证，不是性能等价或生产 GPU serving。

离线包 7.49 GiB（含模型权重）已在本机构建并 smoke test，但**未公开发布**，因此不计入公开可复现声明。

## 边界（不含糊的部分）

- 所有数字只适用于本机硬件、vLLM 0.29.0 与文中条件，不外推到其他 GPU 或长上下文业务。
- BF16 checkpoint 装不进 8GB 显存，它是在 CPU 上分层跑出来的质量基线，**它的延迟不能和 GPU 常驻模型比较**。
- 200 题单选题只能说明“在这 200 题上没观察到差异”，自由文本、代码、长上下文与真实业务数据都需要单独评测。
- 成本计算器是容量成本估算，不含网络、存储、人工、税费与冗余，不能冒充云 API 的完整报价。
- 10 分钟 soak、HPA 和背压测试使用 mock upstream，验证的是网关机制，不是模型吞吐。
